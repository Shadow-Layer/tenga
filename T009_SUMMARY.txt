CONFIGURATION
================================================================================

Quick Start:

Development (SQLite):
  DATABASE_URL=sqlite:///./tenga.db
  python -m pytest tests/

Production (PostgreSQL):
  DATABASE_URL=postgresql://user:password@host/tenga
  DB_POOL_SIZE=20
  DB_MAX_OVERFLOW=30
  python scripts/migrate.py upgrade head
  uvicorn src.main:app

Environment Variables:
  DATABASE_URL          - Database connection string
  DB_POOL_SIZE          - PostgreSQL pool size (default: 10)
  DB_MAX_OVERFLOW       - PostgreSQL max overflow (default: 20)
  SQL_ECHO              - Enable SQL logging (true/false)
  TEST_POSTGRES_URL     - Test PostgreSQL database (optional)

MIGRATION COMMANDS

================================================================================
ARCHITECTURE DECISIONS
================================================================================

1. Why PostgreSQL Primary?
   - Enterprise-grade ACID guarantees
   - Built-in connection pooling
   - Foreign key enforcement
   - Better scalability for multi-tenant
   - SQLite kept for testing/development

2. Why Alembic?
   - SQLAlchemy native integration
   - Version-controlled migrations
   - Reversible (upgrade/downgrade)
   - Auto-generation from models
   - Production-tested standard

3. Why Multi-Tenant Design?
   - All entities scoped to organization_id
   - Complete data isolation
   - Prepared for federation
   - Supports multiple organizations

4. Why Immutable InventoryMovement?
   - Audit trail integrity
   - Prevents accidental data loss
   - Enables reconciliation
   - Regulatory compliance
   - Enforced via SQLAlchemy events

5. Why Stock Cache?
   - O(1) query performance
   - InventoryMovement remains authoritative
   - Updated atomically with movements
   - Can be recomputed if corrupted
